# UX and Product Bible

## Primary design test

A user with no marketing background should understand the screen without training.

## Required page anatomy

Every major workflow page should contain:

1. Clear page title in customer language
2. One-sentence purpose
3. Recommended next action
4. Primary action
5. Current status
6. Recovery or help path

## Dashboard

The dashboard should answer:

- How is marketing performing?
- What needs attention?
- What should I do today?

Avoid turning it into a database summary. Metrics should be clickable and lead to filtered, relevant records.

Recommended blocks:

- Today’s recommended action
- Upcoming scheduled content
- Content awaiting approval
- Recent performance summary
- Important connection or generation issue
- Simple progress toward current goal

## Onboarding

Use a short guided sequence:

1. Business identity
2. Industry/compliance category
3. Products/services
4. Audience
5. Brand personality
6. Primary goal
7. Location/service area
8. Connected channels
9. Existing media import
10. First recommended campaign

Save progress. Explain why each answer matters. Reuse answers everywhere.

## Campaign creation

Preferred novice flow:

1. Choose a goal from recommended goals
2. Accept or edit AI campaign recommendation
3. Select channels
4. Review generated content plan
5. Generate content/media
6. Review in one place
7. Approve and schedule

Advanced controls should be optional.

## Content review

Show:

- Visual preview
- Channel
- Post date/time
- Caption
- Media
- Compliance warning if relevant
- Estimated credits before generation
- Edit, approve, schedule

Do not make the user open multiple unrelated pages to complete review.

## Video generation

Show:

- What will be created
- Expected format and approximate duration
- Credits required
- Progress status
- Cancel/retry behavior
- Failure explanation in plain language
- Generated output preview
- Edit, save, approve, schedule

Do not display misleading progress percentages unless tied to real stages.

## Empty states

Every empty state should offer the most useful next step, not merely say “No items.”

Example:

> You have no scheduled posts yet. Create your first campaign and PostMotive will build a recommended schedule.

## Error messages

Format:

1. What happened
2. What was preserved
3. What the user can do
4. Support/reference code when useful

Never show stack traces or provider payloads.

## Terminology

Prefer:

- “Business profile” over “workspace configuration”
- “Connected accounts” over “OAuth integrations”
- “Create a campaign” over “instantiate workflow”
- “Marketing goal” over “objective taxonomy”
- “Try again” over “rerun job”
- “Credits returned” over “ledger compensation executed”

## Mobile

Critical actions must work on mobile:

- Review and approve
- Schedule
- Upload/select media
- Check generation progress
- Respond to warnings
- View calendar items
- Ask Motive

Avoid horizontally dense tables as the only interface.
